# 04. Data Strategy

## 1. Data Strategy Overview

The data strategy was designed as a core component of the ShrimpSim project.

The objective of ShrimpSim was not only to develop a shrimp farming simulation game, but also to create a sustainable competitive advantage through the collection and utilization of data.

The project proposed the development of a proprietary **Data Moat** that records and accumulates data generated throughout the simulation process. This data ecosystem focuses on three key areas:

- User and learning behavior.
- Technical variables and farming decisions.
- Simulation outcomes and environmental responses.

By continuously collecting and analyzing these data, ShrimpSim was expected to create a growing knowledge base that could support learning analysis, research, and future data-driven applications.

The long-term data strategy can be summarized as:


```text
User Interaction
        ↓
Simulation Decisions
        ↓
Simulation Outcomes
        ↓
Data Collection
        ↓
Data Processing and Storage
        ↓
Analytics and Decision Support
        ↓
Continuous Data Accumulation
        ↓
Data Moat
```

## 2. Data Collected by ShrimpSim

The ShrimpSim platform was designed to generate and collect data throughout the user interaction and simulation process.

The project identified both **structured** and **unstructured data** as part of the platform's data ecosystem.

### 2.1 Structured Data

Structured data includes information that can be organized into predefined fields and stored in databases for analysis.

The main categories include:

| Data Category | Example Data |
|---|---|
| **User Data** | User information and learning-related data |
| **Simulation Data** | Simulation sessions, farming conditions, and technical variables |
| **Decision Data** | Decisions and actions made by users during the simulation |
| **Simulation Outcomes** | Results and performance generated from user decisions and simulation scenarios |

These data allow the project to track how users interact with the platform and evaluate the outcomes generated throughout the simulation process.

### 2.2 Unstructured Data

In addition to structured data, ShrimpSim can generate unstructured information during user interactions.

This includes:

- Interaction logs
- User activity records
- User feedback and responses

These data provide additional information about how users interact with the platform and can support further analysis of user behavior and the simulation experience.

### 2.3 Data Generation Flow

The data generation process can be summarized as follows:

```text
User
  ↓
Interaction with ShrimpSim
  ↓
Simulation Actions and Decisions
  ↓
System Processing
  ↓
Simulation Outcomes
  ↓
Structured and Unstructured Data
  ↓
Storage and Analysis
```

## 3. Additional Data Sources

In addition to data generated directly from the ShrimpSim platform, the project identified several external data sources that could support analysis and future decision-making.

The proposed additional data sources include:

| Data Source | Potential Contribution |
|---|---|
| **Specialized databases** | Domain-specific data and knowledge from aquaculture research institutions and universities. |
| **Water environment monitoring data** | Environmental data collected from shrimp farming areas in coastal provinces. |
| **Community data** | Discussions, feedback, practical experiences, and evaluations from farmers and cooperatives. |
| **Academic data** | Scientific research, technical reports, and other published materials related to shrimp farming. |

These additional sources could complement the data generated by the simulation platform and provide broader context for future analysis.

## 4. Data Volume Requirements

To ensure sufficient data for analysis and future model development, the project proposed a minimum data collection scale.

The proposed requirements were:

- Approximately **2,504 users**.
- Each user generates at least **30 simulation interactions or decisions**.
- Data should be distributed across different time periods and simulation scenarios to ensure adequate representation.

Based on these assumptions, the platform could generate a minimum of:

> **2,504 users × 30 interactions = 75,120 simulation interactions**

This volume represents the proposed minimum data foundation for supporting data analysis and future model development.

### Data Collection Considerations

In addition to the total volume of data, the project emphasized the importance of data distribution.

The collected data should cover:

- Different users.
- Different simulation scenarios.
- Different decisions and interactions.
- Different time periods.

A diverse distribution of data would help improve the representativeness of the dataset and provide a more reliable foundation for analysis and future model training.

## 5. Data Storage and Extraction

### 5.1 Hybrid Data Storage Model

The ShrimpSim platform proposed a hybrid data storage model that combines **Cloud Storage** and an **internal database**.

This model was designed to provide both flexibility and scalability while maintaining greater control over sensitive data.

The proposed storage model was:

| Data Type | Storage Method | Primary Purpose |
|---|---|---|
| **Simulation and behavioral data** | Cloud Storage | Analysis, visualization, and model training |
| **User identification and sensitive information** | Internal database | Security, legal compliance, and access control |
| **Integrated external data** | Cloud Storage | Data synchronization, flexible access, and automated updates |

The combination of Cloud and On-premises storage was intended to support different data requirements within the ShrimpSim ecosystem.

### 5.2 Data Sources and Extraction Mechanism

Data in ShrimpSim was generated from the main sources identified in the project:

1. Data generated through user interactions with the game.
2. System data and simulation results generated by the backend.
3. Relevant external data integrated into the platform's data ecosystem.

The data extraction process was proposed to be automated through middleware services and internal APIs.

This approach was intended to ensure continuity and accuracy throughout the data flow, from data generation to storage and further processing.

The proposed extraction flow can be summarized as:

```text
User Interaction
        │
        ▼
ShrimpSim Platform
        │
        ├── User Behavior and Actions
        │
        ├── Simulation Data
        │
        └── System and Simulation Results
                    │
                    ▼
          Middleware / Internal APIs
                    │
                    ▼
             Data Extraction
                    │
                    ▼
         Cloud / Internal Database
```

### 5.2 Data Update Frequency

The project proposed different update cycles depending on the characteristics of each type of data.

- User behavior and simulation actions: Updated in near real time to support the analysis of user responses and operational effectiveness.
- System and simulation result data: Updated based on the completion of simulation processes.
- External integrated data: Updated according to the availability and update frequency of the corresponding data source.

This flexible update approach was designed to ensure that data could be collected and updated according to its operational characteristics.
